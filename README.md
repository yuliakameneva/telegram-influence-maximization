# Адаптивне моделювання поширення інформації в Telegram (ІНДЗ)

Навчально-дослідницький проєкт: Python-реалізація очищення українського Telegram-корпусу,
побудови **проксі-графа тематичної подібності** й синтетичного порівняння
політик вибору початкових вузлів у моделі **Independent Cascade (IC)**.

**Важливо:** ребра графа утворені з подібності текстів, а не з підтверджених
пересилань. Відображені «активовані вузли» є лише результатом симуляції та
не вимірюють реальних читачів чи психологічного впливу.

## Дані

Відкритий датасет: [Aisberg Telegram News UA](https://huggingface.co/datasets/aisbergpublicorganization/telegram-news-ua-dataset),
файл `data/09_2026.jsonl` (публікації вересня 2026 року).
У дослідженні: 35 750 вихідних записів, 27 815 очищених, 25 852 відібраних
для основного порівняння; 25 назв каналів і 222 ребра графа після фільтрів.

* У ZIP немає оригінального об’ємного корпусу чи 25-МБ файлу
  `posts_prepared.jsonl`. Це запобігає повторному завантаженню публікацій
  у Git і не ускладнює роботу з великими файлами.
* Додаються лише невеликі похідні зведення, графові CSV та файли ручної перевірки
  розмітки, необхідні для частини етапів. **Перед публікацією** перевірити
  можливість поширення позначених текстів відповідно до ліцензії датасету.
* Автоматичні мітки емоційного оформлення не є незалежною експертною оцінкою;
  попередні AI-підказки переглядалися авторкою.

## Середовище та встановлення

Перевіряти на **Python 3.11–3.13**, зокрема локальна реалізація виконувалася
в Python 3.13 / PyCharm. У командному рядку з кореня проєкту:

```powershell
py -3.13 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

На Linux/macOS: `python3 -m venv .venv`, далі `source .venv/bin/activate`.
Якщо `py -3.13` відсутній, використати доступну версію `python` 3.11+.

## Швидка перевірка без датасету

```bash
python -m unittest discover -s tests -v
python scripts/run_experiments.py --mode smoke
```

Тести охоплюють типовий зважений граф, вибір за однакових оцінок, ізольовані
й уже активні вузли, нульову ймовірність передачі, завеликий бюджет,
порожні графи (включно з очікуваною відмовою CLI-читача) та контроль часових вікон.

Генератор тестових графів:

```bash
python scripts/generate_test_data.py --scenario chain --nodes 6
python scripts/generate_test_data.py --scenario disconnected --nodes 5 --output smoke_results/isolates
python scripts/generate_test_data.py --scenario empty --nodes 4 --output smoke_results/empty
```

Порожній граф обробляється модульними функціями, але етап 8 навмисно відхиляє CSV
із порожнім списком ребер, оскільки основний експеримент вимагає реальний граф.

## Відтворення дослідження

Оригінальні десять скриптів залишено в корені без змін; між етапами передаються CSV/JSONL.
Порядок запуску (з кореневої папки):

```bash
# 1–2: базовий аналіз і підготовка корпусу; файл можна завантажити вручну
python telegram_stage1_inspect.py --file 09_2026.jsonl
python telegram_stage2_prepare.py --file 09_2026.jsonl

# 3: формування вибірки й файлів для розмітки
python telegram_stage3_annotation.py

# 4: навчання пілотної моделі на перевірених мітках (додаються CSV)
python telegram_stage4_train.py

# 5: нова вибірка для сліпої перевірки
python telegram_stage5_screen_and_audit.py

# 6: обчислення метрик на збережених перевірених мітках
python telegram_stage6_evaluate.py

# 7: створення тематичного графа за підготовленими текстами
python telegram_stage7_build_proxy_graph.py

# 8–10: базові порівняння, абляції та часовий експеримент
python scripts/run_experiments.py --mode full-experiments --repetitions 120
```

Якщо локального `09_2026.jsonl` немає, етапи 1–2 підтримують завантаження
з Hugging Face без `--file` (потрібен інтернет).

**Ручний крок, який не можна автоматизувати без зміни методики:**
між етапами 3–4 мають бути готові погоджені мітки в
`telegram_labels_reviewed_100.csv`; між етапами 5–6 —
`telegram_stage5_annotation_90_filled.csv`. У наборі є копії використаних
таблиць; їх не слід видавати за незалежно експертно анотовані.

Етап 10 використовує **лише сім попередніх UTC-днів** для вибору вузлів,
а наступні три — тільки як синтетичне тестове середовище.

### Якщо потрібен тільки графовий експеримент без корпусу

```bash
python scripts/run_experiments.py --mode real-graph --repetitions 120
```

Для цього в репозиторії є невеликі оригінальні
`results_september_stage7/stage7_proxy_edges.csv` та
`results_september_stage7/stage7_channel_nodes.csv`.

### Приклади запуску з іншими параметрами

```bash
python telegram_stage8_simulate_adaptive.py --repetitions 10 --budget 4
python telegram_stage10_forward_validation_corrected.py --repetitions 10 --budget 4
```

Другий приклад вимагає наявності `results_september_stage2/posts_prepared.jsonl`.

## Структура

- `telegram_stage1_inspect.py` … `telegram_stage10_forward_validation_corrected.py` — 10 послідовних етапів;
- `tests/` — модульні тести на типові, граничні та вироджені випадки;
- `scripts/generate_test_data.py` — генератор синтетичних графів;
- `scripts/run_experiments.py` — автоматизований запуск графових експериментів;
- `results_september_stage*/` — частина малих результатів-орієнтирів для порівняння;
- `.gitignore` — захист від випадкового завантаження оточення, сирого корпусу й великих результатів.

## Контрольні результати та відтворюваність

При бюджеті `k=4` у сценарії середньої інтенсивності IC Adaptive Degree має
середнє 9,117 синтетично активованих вузлів, Static Greedy — 8,033.
У часовій перевірці 4 дати × 3 сценарії × 120 повторень = **1 440** модельних
реалізацій. Значення залежать від застосованих параметрів, випадкових насінин,
версій середовища й використаних даних.

Додані невеликі довідкові файли зі зведеннями; повторний запуск може перезаписати
відповідні результати. Для ідентичності порівнюйте також SHA-256 вхідного датасету.

## Історія змін Git

У наданому `.rar` відсутня папка `.git`, отже **історію попередніх комітів неможливо перевірити за архівом**. Якщо проєкт уже перебуває під Git, продовжуйте наявну історію. Інакше почніть відстеження змін зараз.
Нові коміти потрібно робити під час реальної роботи, наприклад після перевірки
основних скриптів, після додавання/налагодження тестів і після перевірки відтворення.
**Не створюйте фіктивні старі дати чи вигадану історію розробки.**

### Перші коміти в новому репозиторії

Якщо попередньої історії Git справді не існує, створіть новий репозиторій на GitHub,
а далі з кореня розпакованої папки виконайте:

```bash

git commit -m "Import original research scripts"
```

У прикладі кожен коміт відповідає **реальному змістовному кроку впорядкування
проєкту, виконаному тепер**. Не слід змінювати дати й подавати їх за попередні етапи
дослідження. Перед `git add` перевірте `git status` та вміст таблиць розмітки, які
плануєте опублікувати. Для `git push` додайте адресу власного репозиторію.
